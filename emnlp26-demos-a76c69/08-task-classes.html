How Much Identifiability Does Your Task Need?

Classification, steering, and knowledge editing demand different strengths of identification. Pair each task with an equivalence class — the set of representations your training evidence cannot tell apart — and watch it succeed, fail concretely, or pay for guarantees it never uses.

An identification guarantee fixes how close the learned coordinates must come to the true latents. Each strength is an equivalence class: the set of representations the training evidence cannot tell apart — the weaker the strength, the bigger the set. What this shows

All three maps here are equally consistent with the observed data — nothing in the data alone distinguishes them — and differ only in which structure the identifiability guarantee pins down. That is enough to decide each task. A linear classifier survives any affine mix because linear separability is preserved; steering needs the sentiment subspace separated from topic, or the steering vector drags topic along; editing a single feature needs each element pinned down individually, or the edit rewrites its neighbour inside the block.

The slider makes the same point from the worst-case side: an equivalence class is a set of maps, and the slider walks through its members. At zero leftover mixing a task can succeed below its minimal class, but that is luck of the particular member, not a guarantee — the guarantee must hold for every member, and failure needs only one.

The matrix makes the paper’s point in both directions. Below each task’s minimal class the failure is mechanical, not bad luck; above it the guarantee is real but unused, so demanding elementwise identification everywhere sets the bar higher than most tasks require. The useful question is therefore task-relative: name the equivalence class your task needs, then check whether your evidence delivers it.

What the paper says

“Different tasks may require different strengths of identification. While element-wise identifiability is the strongest guarantee and subsumes the other classes, not every task demands it. Steering, for instance, may benefit from block-wise identifiability when related concepts are distributed across dimensions within a shared subspace.” — Call to Action, “Task-Relative Equivalence Classes”, arXiv:2602.16698
“The practical question is whether the assumptions under which identifiability is guaranteed hold when deployed, and whether the resulting equivalence class suffices for the task at hand.” — §“The Right Question Is Not Enough. Answers Must Be Identifiable”, arXiv:2602.16698

Try this

  1. Set the task to steering and walk the strength up from affine. Watch the topic bar: it snaps to zero exactly at blockwise, the first class that pins down the concept subspace.
  2. Stay on steering × affine (a failing cell) and drag the mixing slider to zero: the topic bar vanishes and the steer “works”. Why does the matrix still say fails? Then select elementwise and drag again — nothing moves, because the class leaves no mixing to scale.
  3. Now switch to knowledge editing at blockwise. Topic stays protected, yet the edit still rewrites s₁. What does elementwise add that removes this — and what would it cost to obtain in practice?
  4. Fill all nine cells, then take one interpretability claim you know (a probe, a steering vector, a model edit) and place it: which equivalence class does its evidence establish, and which cell does its headline claim assume? The paper’s open research question asks exactly this: which equivalence classes are the weakest that suffice empirically.
